# 印尼荣升 · 在线质检报告系统

PT. Prestova Home Living Indonesia（印尼荣升家居生活有限公司）的现场质检系统。
QC 用手机在车间录入，**断网照常干活，有网自动同步**；管理员和观察者在办公室看全厂数据。

- 线上：`https://qc.prestova.workers.dev`（口令进入，见 [角色与口令](#角色与口令)）
- 技术栈只有两样：**一个 HTML 文件**（前端全部，约 850 KB，无框架、无依赖）+
  **一个 Cloudflare Worker**（认证 / 同步 API / 照片直传 R2，数据在 D1）
- push 到 `main` 约 50 秒后自动上线

## 快速开始

**前置**：Node **≥ 22.5**（测试用 `node:sqlite`）。**不需要 `npm install`** ——
构建和测试只用 Node 内置模块，wrangler 只有部署和迁移才用。

```bash
node build-standalone.js        # 改完前端：构建（含四道检查）
node qc-worker/test.mjs         # 服务端测试（134 项）
```

**改前端只改 `前端源文件-prestova-inspection-report.html` 这一个文件。**
`index.html` 是构建产物，但要跟着一起提交（CI 会核对两者一致）。

## 功能一览

### 首页

| 区块 | 内容 |
|---|---|
| 板块卡片 | 六个板块，各显示本地记录份数。QC 只同步近 7 天进过的板块，没进过的显示「—」 |
| 不合格日历 | 热力图，一格一天，当天有不合格报告就标红、越多越深；悬停看是哪几个板块。右边是选中月份六个板块的「不合格 / 已提交」份数，点某个月切换 |
| 公告栏 | 管理员发布，所有人可见，有未读时角标点亮 |
| 最近的报告 | 跨板块最近改过的 8 份，点进去直接打开 |
| 顶栏 | 当前角色、中文 / 印尼语切换、退出登录 |

不合格日历的口径：**只算已提交锁定的**，按检验日期落格，判定沿用各板块自己的（含人工改判）。

### 六个板块

| 板块 | id | 干什么 | 特有功能 |
|---|---|---|---|
| 实验室 | `lab` | 海绵物性测试，每批上 / 中 / 下三支 | 标准表（按品号）、出 A4 检验报告、导出数据 |
| 来料检验 | `iqc` | 面料、海绵、弹簧等来料到货抽检，10 个检查项 | 物料基础资料导入（管理员） |
| 制程检验 | `ipqc` | 各车间工序不良记录 | 产品基础资料导入（管理员）、班次（早班 / 晚班）、导出明细 |
| 成品检验 | `fqc` | 每柜成品抽检，出 A4 两页报告（含照片） | 软硬度、毛重 / 净重自动差值 |
| 装柜检验 | `oqc` | 装柜现场核对与封柜记录 | 导入装柜计划表、货物明细核对 |
| 防火检验 | `cfr1633` | 16 CFR 1633 燃烧测试 | PHRR / THR / 燃烧时间、照片和 PDF 报告附件 |

每个板块三屏：**录入页 / 记录表 / 数据分析**。

**记录表**
- 进板块默认落在记录表，不是录入页 —— 直接进可编辑表单，容易被当成空白表填，
  把几天前做完的报告覆盖掉。
- 默认只看当月，「全部」也封顶 200 行。
- 排序：日期倒序 → 同一天里没提交的在前 → 最后修改的在前。
- 点一行 = 选中它（高亮 + 载入），**不切屏**；点了一行才出现「提交并锁定 / 解除锁定」。
  要进录入页点「查看」。
- 锁状态三重信号：行首圆点（绿已锁 / 黄未锁）、未提交整行压暗、「查看」按钮实心 / 空心。

**数据分析**
- KPI + 月度合格率条形图，跟着筛选联动。
- 区间下拉（当月 / 上个月 / 近 3 / 6 / 12 个月 / 全部）+ 基准日期，可以回看任意月份。
  制程和来料用起止日期框，默认当月 1 号 ~ 今天。
- 合格率口径因板块而异：成品 `(n-不合格)/n`，防火 `pass/(pass+fail)` 不含未评，
  制程 `(qty-不良)/qty`，来料 `(判定-不合格)/判定` 不含待判。
- 成品另有「软硬度分布」：`<5 | [5,6] | (6,7] | (7,8] | (8,9] | (9,10]`，
  即超过下限才进下一档（6 算 5~6）。没填的、不是 0~10 的数单独报个数，不进分母。

**提交并锁定**
- 一个动作，没有「交了还能改」的中间态。锁定后 QC 不能再改，只有管理员能解除。
- 离线也能提交（锁状态跟着记录正常同步）。

### 通用

- **中文 / 印尼语**：界面文案、提示语、看板全部双语；A4 打印件不翻，保持英文 + 中文的正式格式。
- **深色模式**：屏幕跟系统偏好走，A4 打印件永远白纸黑字。

## 角色与口令

登录页选身份 + 输口令，**选哪个身份就必须用那个身份的口令**，不互相顶替。
服务端把角色写进 HMAC 签名的 cookie。

| | QC（检验员） | admin（管理员） | viewer（观察者） |
|---|:-:|:-:|:-:|
| 看记录、打印报告 | ✅ | ✅ | ✅ |
| 录入、提交锁定 | ✅ | ✅ | ❌ |
| 改已锁定的记录 / 解除锁定 | ❌ | ✅ | ❌ |
| 删除记录 | ❌ | ✅ | ❌ |
| 导入基础资料 / 改标准表 | ❌ | ✅ | ❌ |
| 发布公告 | ❌ | ✅ | ❌ |
| 同步范围 | 近 7 天进过的板块 | 全部 | 全部 |

- **权限在服务端**：viewer 的任何非 GET 请求一律 403，已锁记录只有 admin 能 PUT。
  前端另有一份可读的 `qc_role` cookie，只决定显示哪些按钮 —— 改了它最多多看见
  几个按钮，点下去照样 403。
- **配置记录**（标准表、物料 / 产品基础资料、公告）任何角色都不能删，管理员也不行。
- 观察者前端一条都不推：服务端会 403，而 403 会被同步层当成「已被锁定」，
  拿服务端那份覆盖本地 —— 共用平板上换人登录时会冲掉别人还没推上去的数据。

口令是 Worker secret，仓库里没有任何真实值：

```bash
cd qc-worker
npx wrangler secret put QC_PASSCODE          # 检验员
npx wrangler secret put QC_ADMIN_PASSCODE    # 管理员
npx wrangler secret put QC_VIEWER_PASSCODE   # 观察者（不配 = 观察者进不来）
npx wrangler secret put QC_COOKIE_SECRET     # 会话签名，随机长字符串
```

没配 `QC_ADMIN_PASSCODE` 时，`QC_PASSCODE` 仍然能当管理员用（向后兼容）。
观察者**不回退**到 QC 口令。

## 构建

```bash
node build-standalone.js
```

套上 `<head>` 外壳，同时写出 `index.html`（进仓库）和 `qc-worker/public/index.html`
（部署用，不进仓库）。写文件**之前**先跑四道检查，任何一道不过都 `exit 1`、不产出文件：

| 检查 | 拦什么 |
|---|---|
| 板块隔离 | 每个板块的 CSS 必须限定在自己的根节点下（`#lab` / `#iqc` / `#ipqc` / `#oqc` / `#cfr1633`） |
| 品牌串 | 页面里找不到 `Prestova Home Living Indonesia` |
| JS 语法 | 脚本解析不过 = 白屏 |
| id 引用 | 脚本里写了 `"#foo"` 而 HTML 里没有 `id="foo"` |

**这四道只验「能不能跑起来」，不验行为。** 按钮点下去对不对，没有自动化覆盖。

## 部署

**push 到 `main` 就自动部署**（Cloudflare Workers Builds，约 50 秒）。
链路是 `构建 → 产物漂移检查 → 服务端测试 → wrangler deploy`，用 `&&` 串起来，
**任何一道不过都不部署**：

- `git diff --exit-code index.html` —— 改了源文件忘了重新构建就 push，这里当场红。
- `npm test` —— 改坏鉴权不会悄悄上线。

非 `main` 分支也会构建，只上传预览版本、不切线上流量。

> 部署失败是**静默**的：线上继续跑旧版本。刷新没变化时，先强制刷新，
> 再去 GitHub 提交旁的「Workers Builds: qc」检查或 Cloudflare 面板看是不是红了。

面板的具体命令配置、2026-08-24 那次「部署成静态网站、线上坏了 13 小时」的事故，
以及判断线上是否健康的方法，都在 [`qc-worker/README.md`](qc-worker/README.md)。

手动部署（平时不用）：

```bash
node build-standalone.js
cd qc-worker && npx wrangler deploy
```

**回滚**：代码 `npx wrangler rollback --name qc`（每次部署的版本都留着）；
数据走 D1 Time Travel，可回到 30 天内任意时间点。

## 数据库与迁移

三张表：`reports`（记录，payload 是 JSON）、`photos`（照片索引，实体在 R2）、`d1_migrations`。

表结构的**唯一真相源**是 `qc-worker/migrations/`。测试库和本地后端也从这里建表，三处一致。

```bash
cd qc-worker
npm run migrate:list             # 看有没有未应用的迁移
npm run migrate                  # 应用到线上
npm run migrate:new -- 加XX列    # 新建迁移文件
```

> **先迁移，确认无误，再 git push。** push 会立刻部署，新代码读写的列还没加到
> 线上库，中间就是线上 500。反过来是安全的。
>
> **不要手工 `ALTER TABLE`**：不进 `d1_migrations`，重建库时会丢。

## 设计要点

**离线优先。** 数据先落 IndexedDB（`prestova-ir`），页面可见时每 60 秒推拉一次。
冲突用 last-write-wins，输掉的一方拉服务端那份覆盖本地，**并弹提示告诉用户**。
照片单独走 R2，不进 payload。

**按板块过滤同步。** QC 的轮询只拉近 7 天进过的板块（`/api/index?types=…`），
外加几条配置记录；管理员和观察者不过滤，拉全量看全局。照片索引不随轮询下发，
打开记录时从 `/api/report/:id` 现拿。

**两个 store。** `reports` 存完整记录（含照片 Blob），`meta` 存轻量索引。
列表、筛选、看板、同步判断全走 `meta`，只有真要打开一条时才读 `reports`。

> **改了 `metaOf()` 里任何一处推导，就把 `META_VER` 加 1**（当前 `5`）。
> 开机对不上会整表重算索引；不加的话，老设备上新字段永远是 `undefined`。

**锁定靠服务端兜底。** 已锁记录只有 admin 能 PUT —— 这不是安全加固，是功能必需：
少了它，一台还没同步到锁状态的设备照样能改，last-write-wins 会让它赢，把锁冲掉。

**记录表封顶。** 三万条数据不限量渲染会撑出 12 万个 DOM 节点，筛选框敲一下要 4~5 秒。

**中文 / 印尼语。** 静态文案开机时 DOM 走一遍替换，动态文本走 `tr()`；
词典是 `I18N_ID`，语言存 `localStorage`（`qc-lang`）。

## 线上成本

> 2026-08-28 实测，会变，用前复核。

| | 数值 |
|---|---|
| `reports` | 2,395 行（含 509 条删除墓碑） |
| `photos` | 2,943 行 |
| D1 库大小 | 3.06 MB |
| D1 读行数 | 1,912 万 / 天 |

**会先撞墙的只有 D1 读行数**：Workers 免费版 500 万行 / 天（当时已超 3.8 倍），
付费版（$5 / 月）250 亿行 / 月，当时只占 2.3%。读行数几乎全来自轮询的 `/api/index`
全表扫描，代价 = `轮询次数 × 表行数`。观察者也拉全量，**发给很多人之前先把观察者的
轮询放慢**。结构性的下一步是 `/api/index?since=`。

R2 不会是成本问题：100 GB 才 $1.35 / 月，出口流量免费。

## 踩过的坑

**配色 token 分两套，别串。** `:root` 那套是**纸**的配色（`--paper` / `--ink` /
`--fail` / `--pass` / `--accent-soft`），深色模式下不翻面；屏幕组件要用屏幕那套
（`--card` / `--field` / `--no` / `--ok`）。串用就是深色下白底白字，发生过至少四次。

**删字段要全文搜残留引用。** 引用了已删除的标识符语法完全合法，解析检查抓不到，
一进那个板块就 ReferenceError。构建的「id 引用」检查就是为此加的。

**要拿来筛选或分组的字段，一律做成固定词表。** 自由输入框迟早分裂：来料的
「物料类别」出现过两个肉眼一样的值（一个半角括号一个全角）。

**基础资料改了 xlsx 不等于改了应用。** 应用读的是 IndexedDB / D1 里那份快照，
只有在工具栏重新导入才会更新。

**`index.html` 漂移。** 线上部署的是 CI 现建的那份，仓库里那份要靠漂移检查守着，
否则改了源文件不重新构建就 push，线上对、仓库里悄悄过期。

**显隐别交给「顺手」的代码。** 「提交并锁定」按钮原来每次画记录都被放出来，
实验室只是碰巧在载入后又切了一次屏才藏住。现在显隐只归切屏函数和记录表点行两处。

## 不进仓库的东西

真实业务数据（物料表、成品 / 装柜基础资料、1,230+ 批实验室历史、检验照片）和
调试用的 Chrome 配置目录都在 `.gitignore` 里。基础资料在应用里「导入 xlsx」现场加载，
历史数据从服务端同步下来。
